# AR-DB 自己改善・データベース増強案レポート

**作成日**: 2026-05-19
**起点アイデンティティ**: 「学術知の ConceptNet」（2026-05-18 確定）
**目的**: AR-DB の自己観察を活用し、本 DB 群（174 DB / 448 アセット）の構造的改善案を 8 軸対称構造から導出
**典拠**: AR-DB 内部 SQL 監査 + 174 DB の _quality_metadata 走査（2026-05-19 実測）
**制約**: 量を強みに数えない / 既存深化優先 / 客観・忖度なし / アイデンティティ整合性

---

## エグゼクティブ・サマリー

AR-DB の自己観察と 174 DB スキャンで判明した「学術知の ConceptNet」アイデンティティに対する構造的ギャップは以下のとおり：

1. **品質保証軸の薄さが最深**: 174 DB のうち IRR コーエンのカッパ係数を公表している DB はわずか **5 件**。残る 169 DB は評価者間信頼性の業界基準を満たしているか不明。これは ConceptNet との「品質保証で勝つ」差別化が **DB 全体の 3% にしか及んでいない** ことを意味する。
2. **外部知識基盤接続の偏り**: 48 ある参照 DB のうち OpenAlex に紐付け済は **22 件**（45.8%）。半数以上が学術正本層と切れている。
3. **AR-DB 自身の文化バランス警告**: 内部監査で AR-DB の非西洋率が **3.3%**（1/30）と検出された。エコシステム全体の自己観察層が Eurocentric である事実は深刻な構造的不整合。
4. **孤立 DB の存在**: epo-db / foodag-db / pst-db / usj-db など、参照頻度 1 件以下の DB が複数。「学術知の連邦」を名乗る以上、孤立 DB は構造的瑕疵。
5. **物理 DB のカッパ係数 0.50**: 公表値が「中程度の一致」止まり。「世界水準の品質保証」を主張するなら 0.80 超への引き上げが必須。

以上から、増強案の優先順位は **構造を整える** 方向に絞られる。

## 増強案（優先順）

### 【提案 0 ─ 最優先・実行済】品質指標 5 件セット標準化

**2026-05-19 検証結果と実行内容**

外部学術文献検証（PLOS ONE 2019 / PMC 5712640 / Sage Journals 2025 等）により、Cohen のカッパ係数単独公表の方法論的限界が確認された。本エコシステム内でも CEH（broad κ=0.08 / canonical κ=0.99）・ES（broad κ=0.73 / canonical κ=0.93）でカテゴリ粒度による κ の大幅変動が観測され、これはカッパパラドックスの実証例である。

**実行済アクション**:
1. ルール正本化: `~/.claude/rules/quality-metrics-standard.md`（5 件セット標準）
2. 計算ツール実装: `~/projects/research/agent-registry-db/tools/gwet_ac1.py`（自己テスト済）
3. 既存 5 DB へマイグレーション通知記録: `quality_metric_status='kappa_only_legacy_2026_05_19'`
4. 新規測定 DB は初回から 5 件セットで記録（カッパ単独公表禁止）

**5 件セット構成**:
- `observed_agreement`（Po, 生の一致率）
- `gwet_ac1`（Gwet AC1, 推奨主指標）
- `cohens_kappa`（参考値、後方互換）
- `positive_prevalence`（解釈の前提条件）
- `sample_size`（信頼区間判定）

**アイデンティティ寄与度**: 最高。「学術知の ConceptNet」として 2020 年代の学術基準に整合させる必須対応。

#### 提案 1: 評価者間一致度の DB 単位測定を 5 → 50 DB へ展開（5 件セット形式で）

- **着手対象**: 概念 DB 群 30+ を中心に未測定 DB
- **改善する軸**: 5（品質保証）
- **到達水準**: 174 DB のうち 50 DB（28.7%）で Cohen のカッパ係数を公表。物理 DB の 0.50 → 0.80 超への再構築を含む
- **工数見積**: 8〜12 FDD（DB あたり約 0.2 FDD で評価データ作成、カッパ計算、公表）
- **アイデンティティ寄与度**: 最高。「ConceptNet との対称位置で品質で勝つ」差別化を 3% → 28.7% へ拡大。これは ConceptNet が 27 年構築してこなかった領域への明確な前進
- **実行経路**: `/ddb --auto-deepen-all --metric=irr_kappa`

#### 提案 2: AR-DB 自身の非西洋率を 3.3% → 30%+ へ引き上げ

- **着手対象**: agent-registry-db 内のエージェント記述・概念タグ
- **改善する軸**: 6（文化バランス）+ 7（運用主体）
- **到達水準**: 非西洋起源の概念タグ（Ubuntu / Buen Vivir / 鶴見和子 / 清水博 / イスラム経済学 / 中国伝統哲学等）を AR-DB に登録し、エージェントとの関係を構築。30% 以上を達成
- **工数見積**: 2〜3 FDD
- **アイデンティティ寄与度**: 最高。**自己観察層自体が Eurocentric であれば「ConceptNet の対称位置」の主張は内部矛盾を抱える**。この補正は他のすべての改善案の前提条件になる
- **実行経路**: AR-DB スキーマに `cultural_origin` 列追加 + 内容ロード

#### 提案 3: OpenAlex 接続率を 22 → 40 DB（83% 充填）へ拡大

- **着手対象**: 学術領域系で未接続の 26 DB（特に anthropology / poetics / lit / philosophy / kgh など人文学系）
- **改善する軸**: 2（知識源）+ 8（用途）
- **到達水準**: 174 DB のうち学術領域系 48 DB の 83%（40 DB）で OpenAlex 識別子充填率 50% 以上
- **工数見積**: 5〜8 FDD（既存の academic-outcomes-db ETL パイプラインを流用）
- **アイデンティティ寄与度**: 高。OpenAlex を「学術正本層」として位置づけた以上、人文学 DB の未接続は住み分け宣言と矛盾する
- **実行経路**: 既存 OpenAlex ETL を人文系 DB へ並列展開

### 【4 位〜7 位 ─ 構造整備】

#### 提案 4: 孤立 DB 4 件（epo / foodag / pst / usj）の関係性再構築

- **改善する軸**: 3（関係構造）+ 8（用途）
- **到達水準**: 各 DB を最低 5 つの他 DB と cross_db_refs で接続。専属エージェント定義を AR-DB の 5 種関係（calls / orchestrates / observed_by 等）で他エージェントと接続
- **工数見積**: 2 FDD（DB あたり 0.5 FDD）
- **アイデンティティ寄与度**: 中。「学術知の連邦」を名乗る以上、孤立 DB の存在は構造的瑕疵

#### 提案 5: 物理 DB のカッパ係数 0.50 → 0.85 への再構築

- **改善する軸**: 5（品質保証）
- **到達水準**: 評価者間信頼性を「中程度」から「ほぼ完全な一致」へ。データ重複・関係ラベル曖昧性の洗い直し
- **工数見積**: 2〜3 FDD
- **アイデンティティ寄与度**: 中。物理 DB は AR-DB 経由で頻繁に参照される基盤 DB であり、品質低位は他 DB への波及リスクが大きい

#### 提案 6: 数学 DB の非西洋率 15.9% → 35% へ

- **改善する軸**: 6（文化バランス）
- **到達水準**: アラビア数学・中国数学・インド数学・日本和算の概念を追加し、西洋数学との関係を構造化
- **工数見積**: 3 FDD
- **アイデンティティ寄与度**: 中。ConceptNet が Eurocentric であることへの明示的対抗の典型例

#### 提案 7: 領域メタ 6 件（dom-*）の DB 統括カバレッジを 88 → 130 DB へ

- **改善する軸**: 1（目的）+ 3（関係構造）
- **到達水準**: 6 領域メタが直接統括する DB を 174 中 130 DB（74.7%）まで拡張。現状は 88 DB（50.6%）止まり
- **工数見積**: 2 FDD（メタエージェントの description 更新と関係登録）
- **アイデンティティ寄与度**: 中。Tier 1 層の責任範囲が半分しかないのは階層構造の不整合

### 【8〜10 位 ─ 拡張的整備】

#### 提案 8: 概念埋め込みベクトル層（Numberbatch 相当）の自前実装着手

- **改善する軸**: 1（目的）+ 8（用途）
- **到達水準**: 174 DB の主要概念に 300 次元ベクトルを付与。意味類似度検索を可能化
- **工数見積**: 10〜15 FDD（初期構築）
- **アイデンティティ寄与度**: 高い長期戦略。**これが未実装である限り「ConceptNet の学術知版」の主張は機能面で 1 つ欠ける**。ただし短期的優先度は中

#### 提案 9: PostToolUse フックを LLM 呼び出しログにも拡張

- **改善する軸**: 7（運用主体・自己観察）
- **到達水準**: AR-DB が「実行履歴」も観察対象とする。どのエージェントがどのテーマで呼ばれ、どの DB を参照したかの動的観察
- **工数見積**: 3 FDD
- **アイデンティティ寄与度**: 中。自己観察の時間軸（静的定義のみ → 動的実行履歴）への拡張

#### 提案 10: 非西洋学術成果統合 DB の新設（最小規模）

- **改善する軸**: 6（文化バランス）
- **到達水準**: 非西洋の学術ジャーナル・学位論文・伝統学術機関を集約。J-STAGE（日本語）/ CNKI（中国語）/ SciELO（スペイン語・ポルトガル語）/ AJOL（アフリカ）等の統合
- **工数見積**: 8〜10 FDD
- **アイデンティティ寄与度**: 高。新規 DB だが「明確な欠落領域」に該当
- 注: 既存深化優先方針に反するが、欠落領域の補完として例外的に提案

## 西村勇也への次アクション提案 3 件

### A. トップ 2 案の即時着手（合計 10〜15 FDD）

最も緊急性が高く、最も少ない工数で「学術知の ConceptNet」アイデンティティへの整合性を改善できる組み合わせ：

- **提案 1（カッパ係数 50 DB 展開, 8〜12 FDD）**
- **提案 2（AR-DB 非西洋率引き上げ, 2〜3 FDD）**

これらは並列実行可能。提案 2 は前提条件として最優先。

### B. OpenAlex 接続展開の決定（5〜8 FDD）

提案 3 は既存 ETL を流用するため工数効率が良い。人文学系 DB を学術正本層と接続することで、「学術知のインフラ」としての完成度が一段上がる。L1 + L5（先の OpenAlex 連携レポート）の方針と整合的。

### C. 埋め込みベクトル層着手の意思決定保留

提案 8 は ConceptNet Numberbatch に相当する大きな未実装領域だが、10〜15 FDD の工数を要する。トップ 3 案完了後（約 1〜2 ヶ月後）に再評価することを推奨。それまでは「機能ギャップを認識しつつ保留」の状態で良い。
